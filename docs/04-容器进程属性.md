# 容器进程属性

OCI 的 `process` 不仅描述执行什么程序，也描述程序使用的身份、工作目录和资源限制。这些属性由初始化进程设置，后续 `exec` 替换程序时会保留。

## 用户和组

`user.uid` 和 `user.gid` 是数值身份，不要求容器内 `/etc/passwd` 存在对应条目。`additionalGids` 指定附加组，参与文件权限检查；列表为空也必须清空继承的附加组。

Linux 有真实、有效、保存的 UID/GID：真实身份标识进程所属用户，有效身份主要用于权限检查，保存身份允许程序在一定条件下恢复身份。容器初始化使用 `setresgid`、`setresuid` 一起设置三者，避免保留原来的特权身份。

先设置附加组，再设置 GID，最后设置 UID。降权后可能失去修改组的权限。Linux 内核的凭据属于线程，Go 的相关凭据封装会同步进程内各线程；仅锁定一个 OS 线程不能替代这种同步。

## 工作目录

`process.cwd` 是容器内的绝对路径，应在切换 rootfs 后解释。使用最终身份进入目录，才能检查该用户是否有目录搜索权限；目录不存在或不可访问时返回错误，不自动创建。

## 资源限制

`process.rlimits` 指定进程资源限制，例如 `RLIMIT_NOFILE` 限制可打开的文件描述符数量。`soft` 是实际生效的限制，`hard` 是自行提高 soft 的上限，soft 不能超过 hard。未配置的限制保持继承值。

rlimits 主要约束进程，cgroup 则用于管理整个容器的资源。提高 hard 可能需要特权，因此应在降低身份权限前设置。

## 初始化顺序

需要特权的 rootfs 和挂载操作先完成，再设置资源限制与身份，最后进入工作目录。任何设置失败都应终止初始化；已经生效的凭据或限制不尝试整体回滚。后续 capabilities 的设置还需要围绕身份切换安排，不能简单全部放在降权之后。
